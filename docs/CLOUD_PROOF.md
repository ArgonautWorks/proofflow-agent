# Google Cloud deployment proof

ProofFlow uses a real Cloud Firestore database in the Firebase project `proofflow-agent`.

## Runtime evidence

- Public health endpoint: <https://proofflow-agent.vercel.app/api/health>
- Firestore-backed audit: <https://proofflow-agent.vercel.app/api/runs/TiuPE6fJv3JuAamQvAIp>
- Evidence pack generated from that record: <https://proofflow-agent.vercel.app/api/runs/TiuPE6fJv3JuAamQvAIp/report>
- Database: Firestore Standard edition, `(default)` database
- Region: `europe-west4` (Netherlands)
- Billing: Firebase Spark plan, $0/month

The health route performs a server-authenticated Firestore write before returning `"firestore":"connected"`. Audit runs are written to `proof_flow_audits`; pseudonymous daily counters are written to `proof_flow_limits`. The downloaded report is generated by reading the persisted record back from Firestore.

## Access design

Firestore was created with production-mode rules, so browser clients have no direct database access. The Firebase Admin credential is available only to server routes as an encrypted Vercel environment variable. It is excluded by `.gitignore`, is never prefixed with `NEXT_PUBLIC_`, and is never sent to Gemini.
